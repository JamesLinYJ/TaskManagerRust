# 有限状态验证

六个项目技能位于 `.agents/skills/taskmgr-verify-*`。应用程序检查是普通仓库验证文件，位于 `verification/formal/applications/`，不注册为技能。各项包含 TLA+ 模型、当前与负例配置、中文视图及源码对应说明。

| 检查名称 | 检查性质 | 当前结果 |
| --- | --- | --- |
| `worker` | 关闭通知入口后不再发送新的窗口通知 | 通过 |
| `services` | 重启成功之前已经确认停止并发起启动 | 通过 |
| `startup` | 正常退出前按顺序处理已经接受的修改 | 通过 |
| `sessions` | 独立消息逐次保留，重复注销和断开可合并 | 通过 |
| `processes` | 创建时间匹配的进程句柄才交给操作 | 通过 |
| `applications` | 确认后只终止保存身份对应的同一已验证进程对象 | 通过 |
| `sampling` | 缺失或无效读数不成为新的真实零值历史点 | 通过 |

基线为 `7003888753316de6662996112f8e3100ee470208` 加 2026-11-09 工作区修改。16 个 mod.rs 已迁移到同名 .rs；五个覆盖模块仅头部路径变化。Applications 已统一为确认后通过已验证进程句柄终止，共六个技能和一项独立验证、七项当前检查。这是有限模型检查和真实 Rust 函数的受控重放，不是完整 Windows 程序证明。逐项边界见对应验证说明；工具版本与来源见 [工具链说明](formal/TOOLCHAIN.md)。

从包含 `Cargo.toml` 的仓库根目录运行：

```sh
python3 verification/formal/verify.py all --self-test
```

可把 `all` 换成表中的检查名称。结果写入新的临时目录，或通过 `--out` 指定仓库外的新目录。当前完整检查退出码为 **0**。原普通窗口关闭路径已删除；旧 HWND 反例模型保留在 `formal/applications/history/` 中，仅作为历史证据，不计为当前通过性质。旧目标“安全发送窗口关闭消息”因用户要求彻底修复竞态，改为“确认后仅终止保存身份对应的进程”；新模型继续允许窗口复用，执行路径不再读取窗口身份。产品语义变更见 README 和 `confirmed_end_task_request` 的测试。

`--self-test` 编译实际 Rust 函数，以受控 Win32 边界重放关键路径；随后在临时源码副本和模型中引入负例，确认失败，再重跑原始版本。它不会修改产品源码。worker 重放使用标准库单消费者有界通道替身，不证明其与 crossbeam 的所有行为等价。

运行器首先检查覆盖源码的 SHA-256。出现 `SOURCE DRIFT` 时先核对实现和模型，不能只刷新哈希。每次结果按对应验证说明使用 `/statechart` 绘图；覆盖源码变化后可用 `/maintain-formal-verification-skill` 同步验证。
